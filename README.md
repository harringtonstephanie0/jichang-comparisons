<a id="categories"></a>
## 🗂️ 对比分类

### 一对一比较

围绕两家服务中真正影响选择的差异展开。适合已经有候选，希望进一步确认哪一家更符合预算、设备和用途的人。

比较既看各自的优势，也说明条件变化后结论会怎样改变，例如用量增加、需要更多设备，或者主要用途从网页浏览变成持续视频播放。

### 多家横向比较

把多个候选放在相近预算、用量或使用条件下比较，方便缩小选择范围。

同一组比较明确入选范围，区分月付、年付折算和按量方案；表格中的优势、限制和来源采用一致标准，不用某一家的最佳条件去对应另一家的最差情况。

### 场景专项比较

从晚高峰、流媒体、AI、家庭多设备或备用等需求出发，比较不同服务的适配情况。

每个专题集中讨论影响该场景的项目，不要求所有文章都重复一份完整的品牌介绍。

> 这里集中放服务商之间的比较。套餐概念、订阅管理、故障排查等单个问题的详细解答，归入 `jichang-questions` 专题。

<a id="scenarios"></a>
## 🧭 按使用需求找对比

| 使用需求 | 优先看什么 | 还需要一起考虑什么 |
| :--- | :--- | :--- |
| **预算有限、用量不大** | 满足需求的最低实际支出 | 流量余量、支付费用、有效期和续费价格 |
| **视频观看与大流量** | 持续播放表现、额度与计费方式 | 常看内容、播放设备、多人同时使用和节点倍率 |
| **晚高峰容易卡顿** | 相近网络与时段的连续使用结果 | 测试日期、失败情况，以及是否覆盖自己的常用任务 |
| **AI 工具与开发用途** | 具体产品和功能的可用情况 | 网页、应用与开发工具分别验证，账号条件另行确认 |
| **家庭与个人多设备** | 同时在线数量、共享规则和客户端 | 合计流量、电视或路由器适配、后续维护方式 |
| **准备更换现有服务** | 新方案能否解决原来的具体问题 | 剩余权益、新增费用、客户端与配置迁移 |
| **低频使用或备用** | 有效期、闲置成本和启用方式 | 按量不一定不限时，两家服务也不必然互为独立备用 |

<a id="dimensions"></a>
## 📊 多维度对比，看清每项差异

| 比较维度 | 具体查看的内容 |
| :--- | :--- |
| **实际价格** | 标价、购买周期、最低预付金额、支付手续费、外币换算和续费条件 |
| **流量规则** | 额度、倍率、上下行计费、有效期、重置与剩余流量处理 |
| **速度表现** | 网页响应、上传、下载、视频等具体任务，单位与测试对象分别注明 |
| **使用稳定性** | 观察时段、持续时间、中断情况、恢复过程和影响范围 |
| **线路与节点** | 所需地区、线路说明、资源共享范围，以及服务商声明与验证结果 |
| **协议与客户端** | 具体协议、客户端版本、订阅格式和实际导入方式 |
| **流媒体 / AI** | 平台、内容或功能、设备、测试日期与未覆盖范围 |
| **设备与共享** | 可用设备数量、同时在线限制、账号共享范围和共同使用的资源 |
| **服务与退款** | 帮助入口、支持范围、响应记录、退款条件与申请方式 |
| **运营可信度** | 主体说明、维护公告、历史故障处理、条款变化和持续沟通记录 |

不是每个项目都需要填一个分数。已经确认的条件、实际观察的结果和仍然未知的部分，分别写清楚，比一列没有依据的星级更便于选择。

<a id="buying-guide"></a>
## 💡 选购指南与避坑建议

### 价格：先比较要付多少，再比较每 GB 多少钱

月付标价、年付折算月价和一次性流量包，分别对应不同的购买方式。比较时把实际付款、流量额度和有效期一起看。

用量较小，重点是能否以较低支出满足需求；用量较大，再看相同预算下的可用额度。首购优惠之外，还要知道下一次续费按什么价格计算。

### 速度与稳定性：常用任务比宣传峰值更重要

网页打开快、文件下载快和视频长时间流畅，并不是同一份结果。查看测试时，先确认是否覆盖自己的设备、网络和使用时段。

线路标签、协议名称和带宽规格，可以帮助了解服务，但不能单独证明晚高峰体验。记录中的成功、失败和恢复情况应一起看，不只挑最高的一次速度。

### “不跑路”：核对可追溯信息，控制一次性预付

服务是否值得信任，需要结合运营信息、维护沟通、问题处理和退款条款判断。运营年限或一段良好体验，可以作为参考，不能变成未来保证。

月付或其他短周期方式能够减少一次性预付的金额与期限。需要长期购买时，先确认规则、日常表现和退出条件，不只追逐折扣。

### 流媒体、AI 与客户端：把不同条件分开确认

“支持某个平台”应当落实到具体内容或功能；“支持某种协议”还需要对应客户端和订阅格式。宣传中的宽泛标签，不能替代这些细节。

客户端、网络订阅和目标平台账号或会员分别确认。家庭共享也要区分账号权限、流量额度和不同设备的连接方式。

## 📝 信息来源与纠错

价格、功能和服务规则附上对应来源及日期；测试内容另外说明测试者、时间、网络、设备、客户端和具体任务。运营方说明、独立测试与用户反馈分别标注。

价格更新与性能复测分开记录。某篇文章修改过，不代表所有套餐或测试结果都在同一天重新核对。

发现链接失效、价格变更、重要条件遗漏或表述错误，欢迎通过 Issues 或 Pull Request 提供文章位置、正确内容和来源。实际故障反馈尽量描述看到的现象，无法确认原因时，不必先给品牌下结论。

**截图和日志请遮住密码、完整订阅链接、访问令牌、订单号及支付凭据。** 私人订单、退款与账号问题，应联系对应服务商的正式支持渠道。
